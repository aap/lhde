## flxp behavior

* copy/move: Cancel rolls the current top-level item back (a folder copied half-way is removed again); XP keeps
	what was copied. fileops' choice (all or nothing per item), kept for now

* thumbnails that the memory bounds refuse: a progressive JPEG above about 53 MP (libjpeg keeps its coefficients, over the
	160 MB cap), an interlaced PNG, BMP or ICO above 25 MP; a JPEG's embedded EXIF thumbnail (160 px) or a PNG's interlace
	passes read row by row would give them one

* the thumbnail disk cache (~/.cache/thumbnails) is never cleaned: the freedesktop spec leaves it to a cleaner; flxp could
	drop large/ and normal/ entries of files that are gone or not opened for months

## misc

* flxp-filedialog: a right click right after the pointer arrives in the list opens the context menu and closes it at once (seen
	under Xvfb with xdotool mousemove + click 3; tests/headless/filedlg.sh clicks again); a real mouse may never do this, check
	(xdotool's click sends press and release in one burst; Xorg lets such a release past a synchronous grab's freeze,
	tests/headless/menus.sh holds the buttons for that reason: probably the same thing)
* naming pass leftovers: 105 flxp functions and globals with external linkage that no other object references (nm: header::size,
	browser::zoom_at, shell::thumbs::md5_hex, ...): API used only in its own file, or dead; make them file-local or remove them
	component by component

* 4074's About box is Segoe UI 8 under Jade (4074-dwm.png) while MS Shell Dlg is Tahoma: our About box should name Segoe UI in
	its template under the Longhorn styles (the one dialog that does)
* Alt+letter on a menu bar highlights the menu but does not drop its popup (luxpad: Alt+O shows Format highlighted, nothing
	opens; XP opens it); a click and F10 then Down work
* no font fallback in GDI: a character the font lacks is its missing glyph (an emoji in luxpad's Lucida Console is a box,
	stored and saved right); Vista's Uniscribe and fontconfig would take a face that has it
* a message box and a property sheet get minimize and maximize buttons from luxwm (seen in the lab under luna and jade4074;
	luxpad's Find, Replace and Font dialogs too); XP's have Close only (a sheet also ?): wux's fixed-size _MOTIF_WM_HINTS keeps
	MWM_FUNC_MINIMIZE whatever the style's WS_MINIMIZEBOX (an owned dialog is now its owner's transient)

## strings: UTF-8 as wux's only public API (survey 2026-11-12)
* today: 127 W functions, 72 A functions (thin converters; GetACP() = CP_UTF8, so "ANSI" already means UTF-8), 425 neutral;
	flxp/apps call no A function and use std::u16string + a per-file W() helper over w32::utf16_of (an internal header), 323 L""
	literals with (LPCWSTR) casts; the vendored Wine controls are UTF-16 throughout and handle both the A and W item messages
* plan: unsuffixed UTF-8 functions in wux.h (CreateWindowEx, SetWindowText, DrawText, MessageBox, ...) as converters onto the W
	internals, the W names kept for the vendored code only, the A functions deleted; helpers or UTF-8 struct types for the ~40
	string-carrying messages (LVM_/TVM_/TB_/TTM_/SB_/CB_/EM_, WM_SETTEXT/GETTEXT) and the GETDISPINFO notifications (a buffer
	rule), all converting through the one pair (wux/w32/utf.h); both APIs coexist while flxp moves file by file (string-free
	files first: filedlg/main, portal, wallpaper, xwm, preview)
