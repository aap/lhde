## flxp behavior

* copy/move: Cancel rolls the current top-level item back (a folder copied half-way is removed again); XP keeps
	what was copied. fileops' choice (all or nothing per item), kept for now

* thumbnails that the memory bounds refuse: a progressive JPEG above about 53 MP (libjpeg keeps its coefficients, over the
	160 MB cap), an interlaced PNG, BMP or ICO above 25 MP; a JPEG's embedded EXIF thumbnail (160 px) or a PNG's interlace
	passes read row by row would give them one

* thumbnailer entries (shell/thumbs): a thumbnailer child's memory is not bounded (no RLIMIT_AS: posix_spawn has no rlimit
	action; a `prlimit` wrapper or fork+setrlimit would do it); the type is taken from the name only (a PDF without .pdf gets
	none); lhde-postscript renders onto Ghostscript's default page when the file names no page size (an ImageMagick PS
	without setpagedevice is cropped to letter); a timeout leaves the failure marker until the file changes, also when the
	machine was only busy. ffmpegthumbnailer's own entry (videos) and gdk-pixbuf's (GIF, TIFF) work as they are: seen in
	the lab with a generated MP4 and GIF

* the thumbnail disk cache (~/.cache/thumbnails) is never cleaned: the freedesktop spec leaves it to a cleaner; flxp could
	drop large/ and normal/ entries of files that are gone or not opened for months

* Folder Options' File Types: New Action's Browse... (a program through the file dialog) and Create New Extension's
	"Advanced >>" (XP opens it collapsed, the type hidden) are not there; the page's rows show our icon set's file icons, not
	the icon theme's per-type icons; a Restore leaves the empty [Default Applications] / [Added Associations] headers in
	mimeapps.list (GLib does the same); the measurements are ReactOS's template fitted to our 227 x 215 pages, not XP's

* Default Programs (flxp --default-programs): ten radio slots, so a role with more than nine programs offered shows the first
	nine (prefer= order, then by claims); the terminal ([commands] terminal) is no role there yet (candidates from
	Categories=TerminalEmulator, its Exec as the command); XP's "Enable access to this program" check boxes and its
	Computer Manufacturer / Microsoft Windows / Non-Microsoft configurations are not there; the layout is ours (XP's page lives
	in Add or Remove Programs as one scrolled list of groups); with PREFIX=~/.local the role file and make install's
	lhde-mimeapps.list are one path (the role file covers both of its lines, the folders and editor roles)

## strings: UTF-8 as wux's only public API (survey 2026-11-12)
* today: 127 W functions, 72 A functions (thin converters; GetACP() = CP_UTF8, so "ANSI" already means UTF-8), 425 neutral;
	flxp/apps call no A function and use std::u16string + a per-file W() helper over w32::utf16_of (an internal header), 323 L""
	literals with (LPCWSTR) casts; the vendored Wine controls are UTF-16 throughout and handle both the A and W item messages
* plan: unsuffixed UTF-8 functions in wux.h (CreateWindowEx, SetWindowText, DrawText, MessageBox, ...) as converters onto the W
	internals, the W names kept for the vendored code only, the A functions deleted; helpers or UTF-8 struct types for the ~40
	string-carrying messages (LVM_/TVM_/TB_/TTM_/SB_/CB_/EM_, WM_SETTEXT/GETTEXT) and the GETDISPINFO notifications (a buffer
	rule), all converting through the one pair (wux/w32/utf.h); both APIs coexist while flxp moves file by file (string-free
	files first: filedlg/main, portal, wallpaper, xwm, preview)
* Ctrl+digit posts WM_CHAR of the digit (keystate: Ctrl+1 gives char 0x31); Windows gives none for Ctrl+1..9 (only the ASCII
	control characters: Ctrl+A..Z, Ctrl+[, Ctrl+], Ctrl+Backspace's 0x7f)
