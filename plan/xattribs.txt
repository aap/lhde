# Extended attributes

WinFS had some good parts, so use it for some inspiration.

ext4 and zfs support xattrs.
Uses: tagging, metadata, comments/misc annotations
could be especially useful to easier organize agentic workflows

Initially: xattr support for flxp
Future: synchronize local metadata catalog with local and remote filesystems

For existing xattr tooling see ~/src/luxfs [note: perhaps move into lhde? or separate repo...]

Phase 1 is in (columns, the 4051 band's editable rows with invitations, the infotip, Add Tag, the Properties sheet's Metadata
page; docs/USAGE.md "Metadata"). Next phases (plan/XATTR-DESIGN_CLAUDE.md sections 3-4):
* the invitation colour in the 4051 band and the Choose Details dialog's layout are unmeasured choices
* where a colour (user.lux.color) shows is open: the Details column's 12 px square with the name, the band's square after
	the item's name and XP's "Color: Red" line are a first, provisional choice (a square in a column is "a bit ugly"); an
	emblem on the icon, a tinted label or row are the other candidates; the palette (ten names) is a choice too
* saved filters (the Filter box's text kept by name, 4051's "All Photos" queries); an index only if walking xattrs gets slow
* while a filter is on, 4051's band still says "N items in this folder" for the items shown (the status bar says "N of M items")
* tasks as data (a task table with experiences and per-selection names; the research's TASKS-SUMMARY)
* the property registry's defaults in a shipped data file with user overrides (the shape is there, no loading yet)
* luxfs: move into lhde or keep separate
* lhde-import annotates every source's files author = microsoft (lhdetree.annotate_original), also ReactOS's and the free
	source's Pexels photos: a source ini key (author = reactos, ...) would say whose they are
* the Explorer's panes do not follow an attribute changed by another program: inotify's IN_ATTRIB refreshes the rows
	(browser::update), but changed_on_disk() does not refresh the Details rollout / 4051 band of the selection (setfattr in a
	terminal: the pane shows the old value until the selection changes); the Properties sheet refreshes them after OK
* the Properties sheet: a binary value shows escaped (\xNN) in the Advanced list but an edit of it is written back as text;
	the Advanced list's in-place editor is one line, so a value of several lines (notes) cannot be edited there as it is;
	several files with different comments show an empty Comment without the "(several values)" cue (a multi-line edit has
	no cue banner)
* colour display, proposal (aap 2026-11-13: tags stay colourless while the basics are built; colour is a plain attribute, a name
	or hex): draw it as an icon overlay badge, XP's idiom for per-item state (the shortcut arrow bottom left, the shared hand):
	a dot of 8-10 px with a 1 px dark edge at the icon's bottom right in every view, scaled with the icon size; it never
	collides with the selection (the label's highlight) or the shortcut arrow; Finder's underlay reads as a selection and its
	bare dots after the name need a layout per view. Keep the Details column for sorting and grouping. A hex field in the
	Metadata tab beside the swatch row later
